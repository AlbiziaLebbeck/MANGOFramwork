# P7-04 operations implementation contract

Status: in progress. P7-03 implementation is accepted; this document does not certify production backup, alert delivery, RPO or RTO.

## Private monitoring

`GET /internal/metrics` requires a separate collector token of at least32characters; browser/finance credentials do not authorize it. Collector, metrics and financial API routes remain private. A separate single Exact`/health/live` UAT transport preflight serves TLS with an operator-only IP allowlist and exposes no shopper/callback/metrics path. Export only bounded labels and aggregates; never payment/order/identity/file identifiers, reasons, payloads or credentials. Callback histograms/ACK counters reset on restart; durable counts come from PostgreSQL. Work age starts atAvailableAt. Downloaded reports are not missing; provisioning-disabled dependencies are distinct from failures.

Three private targets now cover API, backup and TLS. The TLS observer mounts only the public issued certificate, validates CA/SAN/SNI and exact issued leaf at the fixed NT address, and sends no HTTP request. Backup public-recipient identity/expiry is checked separately from ciphertext capacity/freshness. No private TLS/recovery key is mounted into a probe. Expiry/unavailable rules and explicit public-serving expectation distinguish preparation from an accepted callback endpoint. Source-IP acceptance remains blocked by measured CNI SNAT; the shared Service was only dry-run, not changed.

Package alert rules for callback error/latency, due-job age/retries/expired lease, pending PDFs, unknown Void, open finance cases, missing/quarantined reports, stock invariants, DB/PVC capacity, backup freshness and TLS/key expiry. Do not send Slack/email or configure an external recipient without explicit authorization. A firing dashboard/log is not proof of an on-call notification. Production requires a named receiver and a tested route.

## UAT backup and restore rehearsal

`Operations:RecoveryFreeze` is implemented: all mutation methods (including callbacks) return503 without executing, all three hosted workers stop before leasing work, reads remain available, and health/storefront payment readiness is false. Freeze requires a restart of every API/worker and is an inspection mode, not a live callback-ingest mode. First scale all financial writers to zero, restore, then start only compatible frozen readers for verification. The operations release raises the minimum reader contract to3 so a rollback cannot silently ignore this flag. Current private UAT release`20261019-p7-jwt-lifecycle` meets contract3 and reports recoveryFrozen:false; the older P7-03 contract2 binary must not be treated as freeze-capable merely by setting an unknown environment variable.

## Bank dependency isolation

Each API process has four independent outbound circuit states: Verify QR, Enquiry QR Range, MerchantVoid and Enquiry Void. Defaults are five consecutive transport/server/auth/rate failures followed by a30-second break. After that interval exactly one explicitly requested trial is admitted; no timer, background probe, retry or money-command resend is introduced. Invalid configuration fails startup. Late responses from an older failure generation cannot close a newer circuit, and caller cancellation cannot leave the trial occupied. The metrics use only four fixed service labels and remain available during a database outage. A process restart resets these in-memory states; durable request budgets, send fences and Unknown outcomes still govern financial safety across processes/restarts.

Open-service preflight rejects Verify before consuming its request budget, and MerchantVoid before creating an intent, transaction number, job or send fence. Enquiry Void and inbound callback commit/ACK remain independent. A circuit race after an existing mutation fence preserves the ambiguous outcome and never resends it. A successful HTTP transport trial is not payment confirmation: the ordinary response identity/business-code parser must still establish that result. The HTTP deadline covers response headers and all body reads, including oversized or stalled bodies; the headers-only HttpClient timeout is insufficient with ResponseHeadersRead.

Private capacity telemetry queries the existing mounted filesystem without creating directories or enumerating private objects. Missing mount/capacity is an explicit failed probe, with no fabricated zero-sized filesystem. Independent callback/process/storage signals remain observable when PostgreSQL is unavailable; stale financial/job gauges are omitted.

## UAT backup producer and rehearsal evidence

Use a dedicated read-only PostgreSQL backup role. A UAT-only CronJob exports a consistent custom-format dump to memory scratch, then archives the dump and immutable private assets/documents/reports/finance files. Upload/partial files are excluded. Every referenced final file must be verified after restore; an inconsistent/missing file fails the drill. Snapshot metadata, file hashes and minimum reader contract are retained. Never label a backup complete before the encrypted stream is atomically finalized.

Encrypt before persistent backup storage with OpenSSL CMS AES-256-GCM and an RSA-OAEP/SHA-256 recipient; no private recovery key goes to ntserver02. Keep the UAT recovery key in a Windows CurrentUser DPAPI-protected local file and the public recipient in the UAT job. This is a provisional UAT custodian arrangement, not an approved production key escrow. A separate encrypted copy is pulled to this PC for a real off-server restore drill. A copy on the same VM is not protection against VM loss.

No automatic backup deletion is enabled before company retention approval. The producer enforces a20GiB encrypted-pool budget and reserves at least10GiB or10% (whichever is larger) of the shared node's filesystem free space as measured at start. A kernel-released pool lock serializes manual and scheduled producers; the encrypted output stream also has a hard size cap. The local-path PVC request alone is not treated as a disk quota. Capacity exhaustion fails visibly instead of deleting older recovery points. Other shared-node writers can still change free space concurrently, so monitoring/off-server storage remain required. The cadence cannot be certified continuously until off-server storage/retention is settled.

The user specifically authorized the UAT role/Secret,20GiB pool,15-minute schedule and isolated restore. These resources now exist, both the off-server UAT restore and populated Local financial/file drill passed, and the UAT schedule is enabled. The read-only backup observer mounts ciphertext metadata only, has no SQL/Kubernetes permission or egress, and feeds the private collector. Its scheduling-expected gauge expresses the approved cadence; deliberately suspending the CronJob must be recorded/silenced as an operation, not misreported as an observed Kubernetes state. No automatic off-server copy or retention deletion is enabled. See`TTB_UAT_RECOVERY_EVIDENCE.md` for measured evidence.

The target15-minute schedule is a local UAT backup cadence, not an achieved off-server RPO. Production needs continuous WAL/PITR or an approved equivalent, durable separate storage, capacity/retention policy and tested key recovery. Do not certify RPO≤15m or RTO≤4h until measurements and all required failure domains support those claims.

Restore only to a fresh isolated database/namespace/private directory. Do not overwrite an existing database or erase evidence. Start no API, commerce/PDF worker or bank connection during restoration. Verify archive integrity before extraction, environment identity, schema/reader compatibility, financial references/stock allocations/job effects and every referenced private hash. Use actual synthetic Local commerce data to exercise a meaningful financial restore as well as the currently empty private UAT schema. Preserve Unknown Void/send fences and operation keys; never automatically replay a bank command after recovery.

A production recovery must freeze buyer mutations/fulfillment and reconcile the possible loss interval against bank callback/Verify/report evidence before resuming. Runtime/DB credentials may be reissued separately; historical PGP/JWT/TLS/SFTP keys have separate escrow/rotation lifecycles and must not be silently regenerated or conflated with the backup recipient.

Report archive crypto identities are now snapshotted alongside immutable parser profiles. Planned retired recipient/signing keys require explicit archive-only fingerprint lists; new files remain pinned to current keys. The synthetic two-key PostgreSQL rehearsal covers audited repair, replay and no duplicate money effects. See `TTB_REPORT_OPERATIONS.md` for the rotation procedure and fail-closed legacy/unsigned limits. Actual bank switches, approved JWT deadline policy, PGP expiry telemetry and key escrow are still acceptance gates.

JWT lifecycle telemetry now reads only the existing process-owned key mount and exports fixed expected/usable/scheduled/deadline aggregates, independently of SQL. Missing scheduling metadata is explicit; the application does not infer a bare RSA key's expiry from the JWT/TLS/file timestamps. `TTB_BANK_KEY_ROTATION.md` defines the optional bank/company deadline, atomic projected-file replacement, no previous-key fallback and coordinated bank overlap. Actual bank registration, approved scheduling metadata, PGP expiry/custody and external delivery remain separate gates.

- [OpenSSL x509](https://docs.openssl.org/3.0/man1/openssl-x509/): public validity metadata; no private key is needed for these observations.
- [cert-manager Certificate](https://cert-manager.io/docs/usage/certificate/): certificate/key Secret and automated renewal; this UAT resource uses DNS01 and the existing issuer without changing shared issuer configuration.
