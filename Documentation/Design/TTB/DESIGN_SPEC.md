# MANGOs TTB commerce design specification

18 October 2026. Built-in ImageGen concept set prepared before frontend implementation using Frontend App Builder + imagegen skills. Scope is an HTML/React overlay above Unity, with physical/digital mixed checkout, QR, receipts/history and purchased inventory. No second WebGL engine.

## Concept set and prompt briefs

- `product-desktop.png` — full 1536×1024 product inspection: white MANGOs header; Explore/History/My items; large 1250×760 inspection overlay, 62% Unity preview of terracotta toroidal Orbit Lamp with oval base; 38% detail/price1499/variants/quantity/add-to-cart; rotate/zoom/reset controls; contemporary concrete gallery.
- `checkout-desktop.png` — full 1536×1024 checkout: mixed Orbit Lamp1499 + Mango Star199; buyer name/email/phone; pickup; digital fulfillment explanation; right summary1698; amber Mock notice; create QR action. Same white/forest palette and type.
- `qr-mobile.png` — complete 1024×1536 mobile QR state: MANGOs header, close/back, Mock notice, order reference,1698total, clearly nonfinancial mock QR, expiry, waiting state, save QR, delayed manual verification/shared3checks, order lines and return to gallery.
- `history-desktop.png` — full1536×1024 history: owned paginated open table at left; selected paid order at right with separate physical/digital statuses, immutable receipt number, download/print, inventory action. Same gallery backdrop and controls.

Common generation prompt: actual usable Thai commerce application, code-native Noto Sans Thai labels and controls, bright white #fff, pale neutral gray, forest green #233d33, restrained mango orange,1px dividers,16px panel corners, readable full screens, no marketing hero, fake metrics, unrelated dashboards or claims of bank approval. Assets remain separate from UI text. These four briefs and the saved originals are the design baseline; no separate user design approval was requested because implementation was already authorized and this is not Plan mode.

## Required functional adaptations / fidelity deviations

1. Use the product concept's plain full-width wordmark/header consistently. Checkout's extra mango mark/floating-header treatment is a generation variation, not a new brand requirement.
2. Remove invented ICONSIAM pickup address and descriptions of unverified features. Real company pickup instructions require configuration; UI displays only the selected delivery method and actual catalog description.
3. Prices, options, stock, dates, IDs and payment states come only from API. Show available variants; never fabricate the second swatch or require optional email because the concept marked it mandatory.
4. The QR image is generated by backend QRCoder from the persisted payload. Preserve real QR quiet zones/branding rules. Mock payload is `MANGO-MOCK:…`; do not use the concept's drawn pattern or overlay a mark on a real bank QR.
5. The live product and gallery are native Unity3D geometry/cameras. A raster screenshot cannot replace rotation/zoom. Procedural demo meshes are intentionally code-native3D to match the concept and provide editable demonstrators; merchant production models bind through the model registry. Do not add another browser3D engine. Standalone frontend development can show a labeled product image with rotation disabled until Unity is attached.
6. Hide sample personal details behind empty fields/persist only order reference in sessionStorage scoped to authenticated shopper; no tokens or buyer data in localStorage. Mock mode has a visible notice and local-only simulator controls separate from real Bank mode.
7. Paid, delivery and document readiness remain distinct. Error/retry/expired/finance-review and empty states extend this exact design system. Document print opens verified PDF bytes; it never issues a fresh receipt.
8. UI behind the overlay must remain the actual existing metaverse. The concept's gallery is visual direction for the isolated commerce demo scene, not permission to replace a user's world.

## Fidelity and behavior QA gate

Before final acceptance compare saved concept and actual desktop/mobile screenshots using view_image; record copy, proportions, spacing, type, palette, assets/icons and specific repairs. Run all real API flows plus compiled Unity click/orbit/zoom/focus and mobile pinch. Pending browser/Unity QA is not completion of P6.
